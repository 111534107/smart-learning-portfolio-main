## 1. 目標

把「資管科小助手」從**右下角聊天框**改成**嵌在流程裡、主動幫學生和導師做事的 Agent**，作為專題亮點。

一句話：**學生不用問，小助手在每一步主動整理、分類、提醒、產出草稿；導師打開學生頁就能快速看懂這份備審在寫什麼。所有結果都由本人或導師確認。**

## 4. 共同規則（每一步都要遵守）

1. **身分由登入帳號決定**，AI 不能指定要查誰；導師只能看 `services/teacher_scope.py` 允許的學生。
2. **AI 只能引用系統內已確認的資料**；輸出每一段都要附「依據」（資料筆 ID 或知識庫文件與段落）。查不到就說查不到。
3. **AI 不能寫正式資料**：AI 結果一律是草稿或提醒，由學生或導師按確認才存入。
4. **AI 失效時仍可操作**：沒有金鑰、額度用完、回應格式錯誤時，顯示中文原因，並提供手動方式（例如手動填表、規則排序的推薦清單）。
5. **紀錄**：沿用 `agent_tasks` 記錄每次執行的步驟、狀態、耗時，不記學生原文。
6. **個資告知**：第一次使用會送資料給外部 AI 的功能前，畫面說明哪些資料會送出。
7. **AI 呼叫集中在一個介面**：`gemini_client.generate_json()`；之後組員的多家 AI 切換在這一層替換，步驟程式不用改。

### 10.3 定案設計

1. **導師確認接在 `PackageReview`**：學生按「請導師確認」時，在 `PackageReview` 新增 JSON 欄位存**快照**（當下的事實清單、自傳版本號、完成度）。導師確認的是那一份快照；畫面標出「這一版比上一版新增了什麼」（例：新增勞動部乙級證照）。
2. **確認與撤回都留紀錄**：寫進既有 `AuditLog`，撤回要填原因，原本的確認紀錄保留。
3. **AI 只引用導師確認過的那一版**；學生之後再改，已確認的快照內容不變（可自動測試）。
4. **自傳版本紀錄**：學生或導師每次儲存都新增一版（記錄誰、何時），可以看舊版、比較差異，不能刪；AI 重新產生也是新的一版；AI 摘要標明「依據第 N 版，目前第 M 版」，不貼過期標籤。
5. **導師可直接改自傳文字、留段落意見**；學生看得到老師改了哪裡。多人同時即時編輯延後。
6. **每日用量**：新表記錄「使用者、日期、金鑰種類、次數」，在交易中檢查，避免同時按兩次超額；超過時清楚告知並引導改用自己的金鑰。
7. 舊的成績、證照視為「學生已確認」，不需搬移；之後送審時一起進快照。

### 10.5 第 3 圈（會議 #37～#42）

主持人確認：「下一年級可以看但不能用」＝**(甲)**：專一學生可以看專二、專三要做什麼和二技校系的要求，但不能填寫、不能送審。

補充定案：

- 「最多 5 所」只計算**最新學年度**的校系；舊學年度的校系要在畫面上列出，並且可以刪除（否則新簡章發布後，看不到的舊校系會占住名額，獨立審查 #40）。
- 學生沒填入學學年度、`current_grade()` 回傳 None 時：擋下並提示先補入學學年度，不猜年級。
- 填寫成績、經歷時，年級大於 `current_grade()` 就擋下（`_portfolio_form()`，`student.py:328`）。
- 學生確認沿用現有 `confirmed`；導師確認記在 `PackageReview` 的快照，兩者不共用狀態。
- 導師可以直接改自傳（10.1 B），每次修改都是新版本，並記錄編輯者。
- 不做「一鍵同步到所有校系」。
- （2026-10-09 使用者補充）經歷要學生按「確認」才算學生已確認；未確認的不進自傳事實清單。

主持人回答（2026-10-09 晚，VS Code 對話）：

1. **專一學生可以用「認識科系、看學校要求」的 AI**，算進每天 5 次；用完後提示學生「可以自行貼上自己的 API 金鑰，繼續延伸詢問」。送審相關的 AI（自傳、導師摘要）專一不能用。
2. 11/4 簡報目前沒有指定範本、頁數或報告時間，參考學長姐的簡報（雲端資料夾依專題名稱分資料夾）。
3. 系統基本檢核是科上的標準（113 那份是舊版）。專案裡較新的版本在正式規格書第 331 行「符合資訊軟體開發組要求」：關聯式資料庫、正規化、至少六張資料表、至少兩種非訪客角色、CRUD、統計、輸入防呆、檔案上傳、角色權限、系統架構、ERD、資料字典與需求檢核。

### 10.7 使用者重新檢討的決定（2026-10-10，VS Code 對話）

使用者認為「整個拿掉聊天框」不一定是最好的答案，學生一定會有「系統怎麼操作」的疑問；並重新確認上傳回饋、選校上限與二技公告。**本節取代 10.3 以前與本節衝突的內容。**

| 項目 | 決定 | 說明 |
| --- | --- | --- |
| 小助手怎麼讓學生問問題 | **引導卡片＋「❓ 怎麼操作」說明區＋限定範圍的提問** | ①流程裡的引導卡片是主角（每一步該做什麼、還缺什麼）②說明區用固定的常見問題與一步一步的網頁導覽，不用 AI、不花額度 ③保留提問，但 AI 只回答「系統怎麼操作、科上規定、我的進度」，答案附出處，算進每天 5 次；範圍外的問題禮貌拒絕。取代「拿掉聊天框」 |
| 上傳後 AI 發現問題 | **照 10-07 指導老師的說法：AI 在學生確認畫面旁邊註記** | 讀不到、格式不對、欄位可能有誤，都在學生確認時顯示在旁邊，附「可能原因＋建議怎麼改」，最後由學生本人確認。**不能只寫「錯誤」**，也不要整片紅字：用一般顏色的提示加建議語氣（例：「第 2 頁可能沒拍清楚，建議重新拍攝」）。依據：10-07 逐字稿「不是直接丟給他說錯誤、錯誤……AI 就會在旁邊註記說他有發現幾個點是錯的，因為你一定要本人確認」 |
| 選目標校系的上限 | **一到四年級不限；五年級做備審時最多 5 所** | 低年級選的是「想去的學校」，用來引導方向，隨時可以換。五年級開始做備審資料時，同時最多 5 所（仍只算最新學年度）；五年級還是可以換，但換掉時提醒「已經寫好的自傳要重寫」。取代 10.4「同時最多 5 所」不分年級的做法 |
| 選校的提醒文字 | 畫面要寫清楚 | 「這只是幫你找方向，過程中隨時可以換學校」「五年級做備審資料時只能選 5 所」「五年級換學校，已經寫好的自傳要重寫，會浪費時間」 |
| 二技招生資料的來源 | **小助手的 AI 代理查二技學校資料，只存文字** | 只留申請入學連結、資格、要交的文件、時程、加權等文字，**不下載整個網站**。`school/Documents/116二技技優甄審_時程與備審加權_修訂版.pdf` 是去年（115）的資料，先當示範資料與比對用 |
| 資料正確性 | **管理員核對後才公告** | AI 查到的先當「候選資料」並附官方來源連結；管理員核對後才公告。接在現有「招生資料 Agent」的候選版本與核准流程上 |
| 二技公告給誰 | **四種使用者都會用到** | 學生：二技簡章什麼時候出來、各校要求；老師：收到通知，提醒對應要升二技年級的學生；科辦：知道要補哪些科辦開得出來的證明（學生自己漏傳的獎狀科辦不處理）；管理員：核對與維護資料 |
| 一年級的學校介紹 | 用查到的資料介紹各校特色與優點 | 選校系不寫死，搭配上面的提醒文字 |
