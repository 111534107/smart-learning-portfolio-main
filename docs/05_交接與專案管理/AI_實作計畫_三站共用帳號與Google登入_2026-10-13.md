# 三站共用帳號與 Google 登入實作計畫

> **執行提醒：**此計畫核准後採單一工程師逐站執行；每完成一站及其測試後再進下一站。依專案規則不啟動子代理。

**目標：**在 `ai`、`ai-personal`、`ai-team` 三個獨立學習歷程系統建立一致的帳號名冊匯入流程，讓學生可用帳密或 Google 登入，並由每站自己的資料庫授權。

**架構：**使用共用欄位格式的名冊 CSV（不包含密碼），管理員在每站匯入預覽表格逐列輸入密碼，系統各自建立本地帳號。每站獨立保存密碼雜湊、學籍狀態與 Google `sub`；不建立中央帳號服務、不共用 session。Google 登入只連結有效名冊中的學生，OAuth 設定與核准名冊缺一時不啟用。

**技術棧：**Python 3、Flask 3、Flask-SQLAlchemy、Flask-Migrate、Jinja2、Werkzeug 密碼雜湊、Google 官方 OAuth／ID Token 驗證套件、pytest；測試使用 SQLite 假資料且不得連線 Google。

**規格：**[跨專案共用帳號與 Google 學生登入設計規格](../../02_需求與設計/AI_設計規格_跨專案帳號與登入_2026-10-13.md)

## 全域限制

- 第一階段只用假名冊；不寫入真實姓名、學號、學校信箱、密碼或 Google token。
- 學號格式、學校信箱網域都不能單獨證明在學；Google 登入還須比對有效名冊與帳號狀態。
- 名冊 CSV 不得有密碼欄；密碼只經管理頁送入後端並保存為雜湊，不回顯、不記錄、不寫入瀏覽器本機儲存。
- 三站的 session、資料庫與 migration 鏈各自獨立；不能假設 migration revision 相同或使用同一資料庫。
- 使用者既有未提交差異一律保留。每個 repo 動工前，檢查工作樹與目標檔案差異，只修改本計畫必要範圍。
- Google Client Secret 只放本機／部署環境變數；只維護 `.env.example` 範例名稱，不寫入 Git。
- 不設定實際 OAuth Client、不匯入真實名冊、不套用正式資料庫 migration、不部署或推送。
- 每站修改後更新該站 `docs/03_開發紀錄/development-log.md`；若日誌有別人的未提交差異，先保留原文並依該站代理規則處理。

## 變更檔案盤點

### 共用欄位與每站後端

下列路徑各自在三個 repo 修改；不可跨 repo 共用實體檔案：

- `app/models/user.py`：新增唯一且可為空的 Google `sub`；在既有 `StudentProfile` 增加獨立於 `User.is_active` 的在學狀態（`unverified`、`active`、`inactive`）。
- `app/routes/main.py`：保留原帳密登入；新增 Google 開始授權與回呼端點，檢查登入狀態、CSRF state、回呼與失敗情境。
- `app/routes/admin.py`：在帳號管理加入名冊上傳、預覽與批次建立端點，限管理員使用。
- `app/services/account_batch_service.py`（新增）：解析不含密碼的名冊列、驗證欄位、回報錯誤，並以單一交易建立新帳號。
- `app/services/google_identity_service.py`（新增）：OAuth 授權資料交換、ID token 驗證、名冊比對與 Google 身分連結。
- `app/config.py`：新增 OAuth 開關所需設定；只有 Client ID、Client Secret、回呼 URI、Workspace 網域與名冊功能均設定時才啟用登入。
- `.env.example`：列出 OAuth 環境變數名稱與空值／安全範例，不放有效憑證。
- `requirements.txt`：加入 OAuth／Google 驗證所需且鎖定相容版本的官方套件。
- `migrations/versions/<各 repo 新 revision>.py`：各自新增 `google_sub` 唯一欄位及學生在學狀態欄位；既有學生回填 `unverified`，保留各 repo 現有 migration 父節點與歷史。
- `app/templates/login.html`：僅在 OAuth 設定與名冊功能可用時顯示 Google 登入；保留帳密欄位。
- `app/templates/admin_accounts.html`：加入 CSV 上傳、錯誤列預覽、逐列密碼欄及不含密碼的建立結果；不在 HTML、JS 或瀏覽器儲存中保留密碼。
- `tests/fixtures/fake_student_roster.csv`（新增）：共用欄位的假名冊，僅放假姓名、格式測試用學號、假校務信箱與有效／停用狀態；不含密碼。
- `tests/test_account_batch.py`、`tests/test_google_identity.py`（新增）：分別測試整批驗證與 OAuth／名冊連結。
- `tests/test_auth.py`、`tests/test_admin_management.py`：補充回歸測試；保留既有案例與其他修改。

### 專案差異注意

- `ai` 已有本機示範啟動器 `scripts/run_demo.py` 和展示帳密區塊。不得破壞它；此次新增的是管理員批次名冊與 Google 學生登入。
- `ai-personal` 的登入／管理頁與其他兩站版面不同，且 `tests/test_auth.py` 已有未提交的本機開發測試帳密變更。實作時先讀該檔差異，將先前核准的「僅本機、由環境變數提供測試帳密」需求整合進同一檔案，不可覆蓋或刪除既有測試。
- `ai-team` 與 `ai-personal` 共用近似管理頁，但仍是不同 Git repo，必須各自新增 migration、路由與測試，不用複製 `.git` 或搬移資料。
- 三站目前共用相似的 `User` 欄位，不代表資料表 schema／migration head／所有功能完全相同；以各自原始碼與測試作準。

## 完成定義

- 三站各自完整測試通過，migration 在各自測試資料庫升級／降級成功。
- 三站有一致的假名冊 CSV 規格和管理頁批次建立結果。
- Google 驗證案例通過，無 OAuth 設定時不會啟用登入按鈕；只有拿到 OAuth 設定和核准名冊後才能做真實登入驗收。
- 密碼只以雜湊保存；差異檢查與假資料掃描通過；每站日誌與計畫狀態更新完成。
- 不推送、不部署、不套用正式資料庫 migration，不操作真實名冊。
