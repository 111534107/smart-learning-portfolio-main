## 四、反向代理：讓系統拿到真正的來源 IP

用到來源 IP 的地方：管理員登入失敗鎖定（同一 IP 5 次鎖 15 分鐘）、管理員限學校網段、操作紀錄的 IP（`app/services/admin_guard.py`、`audit_service.py` 都讀 `request.remote_addr`）。放在 Nginx／IIS／Apache 後面時，`remote_addr` 會變成代理的位址（通常 `127.0.0.1`），結果是：所有人共用一個 IP 被一起鎖、網段限制失效。

**目前程式沒有處理**，上線前要做兩件事：

1. **代理那端**送出真正 IP（Nginx 範例）：

   ```nginx
   proxy_set_header Host              $host;
   proxy_set_header X-Real-IP         $remote_addr;
   proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
   proxy_set_header X-Forwarded-Proto $scheme;
   ```

2. **程式這端**在 `create_app` 套用 Werkzeug 的 `ProxyFix`（屬於程式修改，本任務不改，請另開工作）：

   ```python
   from werkzeug.middleware.proxy_fix import ProxyFix
   app.wsgi_app = ProxyFix(app.wsgi_app, x_for=1, x_proto=1, x_host=1)
   ```

   `x_for=1` 表示只信任一層代理；有兩層（例如 Cloudflare＋Nginx）就設 2。**不要在沒有代理時開啟**，否則使用者可自己偽造 `X-Forwarded-For` 繞過鎖定。建議用環境變數（例如 `TRUSTED_PROXY_COUNT`）控制，預設 0＝不套用。
3. 驗證：從另一台電腦連線故意輸錯管理員密碼，操作紀錄的 IP 應該是那台電腦的 IP，而不是 `127.0.0.1`。
4. Google 回呼網址必須是 `https://`；`x_proto=1` 讓 Flask 知道外面是 HTTPS，產生的回呼網址才正確。
