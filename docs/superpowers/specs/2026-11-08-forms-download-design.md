# 表單下載區（UC-28／F-53）設計

日期：2026-11-08（台灣時間）
來源：正式規格書 UC-28／F-53；`docs/02_需求與設計/02_設計規格/AI_設計規格_科辦表單區_下載與收件_2026-10-08.md`（第十一點第 1 步「下載區」）；主對話轉述的使用者確認範圍（2026-11-08）。
流程圖：圖 10。

## 一、為什麼做

學生和老師找科上的表單要到資管科網站翻，網站表單又不齊。科辦需要一個自己能上架、改版、下架的地方；學生與老師只看到開放給自己、而且上架中的表單，下載的一定是最新版。

## 二、目標與不做

| 做 | 不做（本版） |
| --- | --- |
| 科辦管理分類（新增、改名、排序、停用） | **收件**（學生繳回、收件清單、退件）：2026-10-09 暫停 |
| 科辦上架表單：名稱、說明、分類、開放學生／老師／兩者、檔案 | 線上填寫、通知、小助手「查表單」工具 |
| 改版＝新增一個版本，舊版保留、不能覆寫 | 刪除表單或版本（只能下架；不刪檔） |
| 下架與重新上架 | 教師上架 |
| 學生、老師 `/forms` 依分類列出可下載表單、下載最新版 | 下載教務處真實檔案（示範只放合成檔） |
| 合成示範表單，讓展示站有東西 | |

失敗的情況（即使能動也算失敗）：學生能下載只開放老師的表單、下架的表單用網址還能下載、改版把舊檔蓋掉。

## 三、角色與權限

| 角色 | 可以 | 不可以 |
| --- | --- | --- |
| 科辦 `staff` | `/staff/forms` 全部管理功能；下載任何版本（含已下架、舊版） | 刪除、覆寫版本 |
| 學生 | `/forms` 看與下載「上架中＋開放學生＋分類啟用中」的最新版 | 進 `/staff/forms`；下載只開放老師、已下架或分類停用的表單（403） |
| 老師 | 同學生，但條件是「開放老師」 | 同上 |
| 管理者 `admin` | 不在本版範圍（科辦頁面沿用現有 `role_required("staff")`） | — |

規則集中在一個函式 `can_download(user, item)`，清單與下載共用，避免兩邊不一致。不存在的表單回 404；存在但無權限回 403。

## 四、資料表

沿用 10-08 規格的表名，只做下載區需要的欄位（收件相關的表不建）。

- `form_categories`：`id`、`name`（唯一，最長 50）、`sort_order`（整數，小的在前）、`is_active`、`created_at`。
- `form_items`：`id`、`category_id`、`title`（最長 100）、`description`（文字，可空）、`open_to_students`、`open_to_teachers`、`is_published`、`created_by_id`、`created_at`、`updated_at`。
- `form_item_versions`：`id`、`item_id`、`version_no`（1 起算，同一表單唯一）、`file_path`（storage_service 回傳的位置）、`original_filename`、`file_size`、`file_sha256`、`note`（改版說明，可空）、`uploaded_by_id`、`created_at`。**沒有任何更新版本列的程式路徑**。

Alembic：新 revision `b20261108f01`，`down_revision = "b20261105c01"`（本分支 11-08 的 head）。其他對話同時新增 migration，合併時會有多個 head，需要再補一個 merge revision；日誌會註明。

## 五、上傳規則

- 副檔名白名單：`pdf, doc, docx, xls, xlsx, odt, ods`（設定 `FORM_ALLOWED_EXTENSIONS`）。
- 內容檢查（簡易 MIME）：PDF 開頭要是 `%PDF`；docx/xlsx/odt/ods 是 ZIP（`PK\x03\x04`）；doc/xls 是 OLE（`D0 CF 11 E0`）。副檔名與內容對不上就拒收。
- 大小：單檔上限 `FORM_MAX_BYTES`，預設 10MB（與全站 `MAX_CONTENT_LENGTH` 一致；超過全站上限時沿用現有 413 頁面）。空檔拒收。
- 檔名用現有 `validate_upload_filename` 清理；儲存用 `storage_service.save(data, owner_id=科辦 id, folder="forms", filename=...)`，跟著系統目前的儲存方式（本機或 Google 雲端硬碟）。
- 下載用 `storage_service.local_path` 取檔、`send_file(as_attachment=True)`，下載檔名是原始檔名；檔案不見回 404。

## 六、畫面

### `/staff/forms`（科辦，選單「表單下載區」）
- 上方「上架新表單」：分類、名稱、說明、開放對象（學生、老師兩個勾選框，至少勾一個）、檔案。
- 表單清單依分類分組（`<details>`，預設展開），每列：名稱、開放對象、狀態（上架中／已下架）、目前版本「第 N 版 · 日期」、「管理」按鈕。
- 「分類」區：新增分類；每個分類可改名、改排序、停用／啟用。已停用分類的表單學生老師看不到。分類不提供刪除。

### `/staff/forms/<id>`（科辦單一表單）
- 編輯名稱、說明、分類、開放對象。
- 上傳新版本（檔案＋改版說明）。
- 版本紀錄：每一版的版本號、檔名、大小、上傳者、時間、下載連結；最新版標「目前版本」。
- 下架／重新上架按鈕。

### `/forms`（學生、老師）
- 依分類分成可收合區塊（原生 `<details>`），標題顯示數量，例如「實習（3）」。
- 每項顯示名稱、說明、最新版日期、檔案類型，「下載」按鈕。
- 上方關鍵字搜尋（GET `q`，比對名稱與說明）。
- 沒有任何表單時顯示說明文字。

### 入口
- 科辦：`partials/nav.html` staff 選單加「表單下載區」。
- 老師：teacher 選單加「表單下載」。
- 學生：學生導覽列另一個對話（student-nav）正在改，本分支**只在學生刊頭右側連結區加一個「表單下載」小連結**（和「怎麼操作」並列），不動主選單項目；日誌註明，合併時由 student-nav 決定最後位置。

## 七、稽核

寫入 `audit_logs`（只記代碼與編號，不記檔名）：`form.publish`（上架新表單）、`form.new_version`、`form.update`、`form.unpublish`、`form.republish`、`form_category.create`、`form_category.update`。`ACTION_LABELS` 補中文。

## 八、示範資料

- 函式 `form_library_service.seed_demo_forms(staff_user)`：4 個分類（實習、專題、常用表格、相關法規，取自資管科網站表單頁分類），約 8 份表單；檔案是程式產生的極小 PDF，內容寫明「合成示範檔，非學校正式表單」。
- 一份「兩者都開放」且有第 2 版（展示改版）、一份只開放老師、一份已下架。
- 呼叫點：`app/demo.py`（本機展示站）與 `scripts/run_demo.py` 各加一行。

## 九、驗收

1. 只開放老師的表單：老師看得到、下載成功；學生清單看不到、直接用網址 403。
2. 改版後下載拿到新內容，舊版在科辦頁仍可下載，版本號遞增。
3. 下架後學生老師清單看不到、網址 403；重新上架恢復。
4. 分類停用後其表單不出現、不能下載。
5. 學生、老師進 `/staff/forms` 與送出上傳都 403。
6. 錯誤副檔名、內容與副檔名不符、空檔、超過大小都拒收，資料庫沒有新增。
7. 上架、改版、下架寫入 `audit_logs`。
8. Migration 升級建出三張表、降級移除。
9. 瀏覽器用合成資料走：科辦上架 → 改版 → 學生下載到新版 → 下架後學生看不到。

## 十、交給實作者決定的（並已決定）

- 科辦管理頁只開給 `staff`（與現有科辦頁一致），`admin` 不加；10-08 規格寫「admin 與科辦相同（備用）」，本版不做，我的判斷。
- 分類不提供刪除，只能停用（避免刪到有表單的分類），我的判斷。
- 不建 `item_type` 欄位：收件暫停，之後要做再加 migration，我的判斷。
