## 二、過去已完成（10 月上旬～10/22）

**學生主線**（上傳證明 → 辨識 → 學生確認 → 學習證據 → 有依據的自傳 → 導師確認送審版）
- 登入與四種角色權限：學生、班導、科辦、管理者。學生看不到別人的資料，導師只看得到本班。
- 「我的五年」首頁與新生引導。
- 成績單、證照上傳後在本機辨識（RapidOCR，原始圖片不送外部 AI），學生檢查修正後按確認才寫進正式資料。
- 規則檢查：分數 0～100、學分合理、課名對照課綱、辨識信心低的欄位標出來。
- 每筆確認過的資料有固定證據編號（F1、F2…），自傳每段都標出用了哪幾筆。
- 送導師確認時固定一份快照；學生之後再改，不影響導師看的版本。導師可以確認，或寫修改建議。
- 電子獎狀：學生申請，科辦核准後產出，任何人都能用驗證碼查真偽。

**升學 Agent（老師 10/21 要求「Agent 要分工」）**
- 一個 Agent 引擎、多組工具：媒合排序、學生條件、自傳、雲端檔案。Gemini 自己決定下一步用哪個工具；AI 不能用時改走固定流程，結果仍然完整。
- 推薦排序：全部校系分成可報、需確認、不可報，每一間都寫理由（不能報的也說明原因）。
- 插大（轉學考）北中南示範資料：寫明插幾年級、考什麼科目。
- 學群判斷：用已確認的成績對照課綱，判斷學生屬於哪個學群，相關科系排前面。
- 招生時程頁：115 學年度二技技優甄審官方日程，每列附出處。
- 背景巡查：Agent 定期檢查招生網站有沒有更新，擷取成「候選」資料，管理員核准後才生效。

## 六、可能被問的問題（照實回答）

| 問題 | 建議回答 |
| --- | --- |
| 完成幾 %？ | V1 主線 14 項全部完成；Agent 擴充範圍約 75%。正式環境驗收（MySQL、Google）排在 11 月中，所以不說「做完了」。 |
| 契合度是錄取機率嗎？ | 不是。是「你的資料對這間學校的甄審加權準備了多少」，畫面上每一頁都有寫。 |
| AI 會不會亂寫自傳？ | 會，所以有三道防線：只給 AI 已確認的資料（不含姓名學號）、每段標出依據、逐句檢查找不到依據的句子。最後要學生自己改、導師確認。 |
| Agent 怎麼分工？ | 一個 Agent 引擎，依任務呼叫不同工具組（媒合排序、學生條件、自傳、雲端檔案）；畫面上看得到它用了哪幾組、順序如何。 |
| 雲端硬碟能用嗎？ | 程式已經做成可以切換（本機或 Google 雲端硬碟），但還沒用真的 Google 帳號實測，所以目前展示存在本機。 |
| 資料會不會外流？ | 成績單、證照在自己的伺服器上辨識，原始圖片不送外部 AI；送給 Gemini 前會去掉姓名、學號；操作都留紀錄。 |
| 跟學長姐的系統差在哪？ | 自傳每句可追溯依據、Agent 分工看得見、資格條件依簡章原文判斷，看不懂的一律「需確認」不亂判。 |
| 為什麼不算錄取機率？ | 沒有可靠的歷年錄取資料，硬算會誤導學生（規格「不做的事」）。 |
