# 雙重驗證：Authenticator 六位數驗證碼教學

> 建立：2026-11-09（Claude）｜狀態：**功能已完成**（2026-11-09），見第四節。
> 決定來源：使用者 2026-11-09 同意用 Authenticator，不用電子郵件驗證碼。

---

## 一、這是什麼

登入時除了帳號密碼，還要輸入手機上 Authenticator App 顯示的**六位數字**。這組數字每 30 秒換一次。

- **為什麼比較安全**：密碼被偷了，別人沒有你的手機，還是登不進去。
- **為什麼不用寄信**：驗證碼由手機自己算出來，不用網路、不用等信，也不會被當成垃圾信。
- **原理**（不用背）：系統和手機共用一把「金鑰」。兩邊都用「金鑰＋現在時間」算出同一組六位數，對得上就代表是本人。這個方法叫 TOTP，是國際標準（RFC 6238）。Google、Microsoft 的雙重驗證都用這套。

---

## 二、誰要開

**所有使用者都要開**（使用者 2026-11-09 決定：關乎個資法與資安，不確定時一律都加）。學生、導師、科辦、管理員都一樣；用帳號密碼或學校 Google 一鍵登入都要。

- 正式環境：`.env` 的 `TWO_FACTOR_REQUIRED` 預設是開（`true`）。第一次登入會先要求設定，設定完才進得了系統。
- 本機展示站與自動化測試：預設**不強制**，因為展示帳號密碼公開寫在登入頁，每次展示都要掃 QR code 不實際。但功能照樣能用：登入後從右上角帳號選單「雙重驗證」開啟，之後這個帳號登入就要輸入驗證碼。
- 想在展示站也強制：啟動前設定環境變數 `TWO_FACTOR_REQUIRED=true` 不會生效（展示站固定不強制）；要展示強制流程，用正式設定啟動即可。

## 三、使用者怎麼設定

### 第一次設定

1. 手機安裝任一款 Authenticator App（都免費，選一個就好）：
   - Google Authenticator（Android／iPhone）
   - Microsoft Authenticator（Android／iPhone）
2. 第一次登入時系統會直接帶你到設定頁；之後也可以從右上角帳號選單 → **「雙重驗證」** 管理。
3. 畫面會出現一個 **QR code** 和一串英數字（金鑰）。
4. 打開手機 App → 按「＋」→「掃描 QR code」→ 對準畫面。
   - 掃不到時，改選「輸入設定金鑰」，把那串英數字打進去。
5. App 會出現「資管科學習歷程（你的帳號）」和一組六位數字。
6. 把**目前的六位數**輸入系統 →「確認開啟」。
7. 系統會給你 **10 組備用碼**。請抄下來或印出來收好，手機遺失時用。每組只能用一次。

### 之後每次登入

1. 輸入帳號、密碼。
2. 系統要求輸入驗證碼 → 打開手機 App，輸入現在顯示的六位數。
3. 數字快換掉時（App 上的倒數快結束）可以等下一組再輸入。

### 手機換了或遺失

- **有備用碼**：登入時改按「使用備用碼」，輸入其中一組 → 進去後重新設定雙重驗證。
- **沒有備用碼**：請管理員在「帳號管理」按「重設雙重驗證」。管理員重設後，你下次登入要重新掃 QR code。
- **管理員自己的手機遺失**：要用伺服器指令重設（見第五節），所以管理員一定要收好備用碼。

### 常見問題

| 狀況 | 原因與處理 |
| --- | --- |
| 輸入正確的數字卻顯示錯誤 | 手機時間不準。到手機「設定 → 日期與時間」開啟「自動設定」。系統會接受前後 30 秒內的數字。 |
| 換了新手機 | 舊手機還在的話，先在系統裡關閉雙重驗證再重新設定；舊手機不在了就用備用碼。 |
| 一直輸入錯誤 | 連續錯 5 次會暫停登入 15 分鐘，避免被猜密碼。 |

### 實作重點（給接手的人）

- 程式：`app/services/two_factor.py`（加密、驗證、備用碼、重設）、`app/routes/two_factor.py`（頁面）、`app/routes/main.py::_finish_login`（登入分流）。
- 登入流程：密碼或 Google 驗證成功後，**還沒寫入 `session["user_id"]`**，只記「等待第二步」的帳號；第二步成功才由 `_complete_login` 真正登入。所以既有頁面的權限檢查都不用改。
- 金鑰用 `cryptography` 的 Fernet 加密後存放。加密金鑰取 `.env` 的 `TWO_FACTOR_KEY`，沒設就由 `SECRET_KEY` 推導。**換了 `SECRET_KEY`（且沒設 `TWO_FACTOR_KEY`）所有人都要重設雙重驗證**，正式環境建議另外設 `TWO_FACTOR_KEY`。
- 驗證接受前後 30 秒；記下最後用過的時間窗，同一組碼不能再用。
- 備用碼 10 組、8 碼（去掉 0、o、1、l、i），只存雜湊值。
- 連續錯誤次數記在 session：錯 5 次暫停 15 分鐘；每次錯誤寫操作紀錄。
- 開啟、重設、使用備用碼、重產備用碼、驗證錯誤都寫進操作紀錄（`audit_logs`）。

## 五、安裝與移除（專題結束要能完整清除）

### 安裝了什麼

| 項目 | 位置 | 來源 |
| --- | --- | --- |
| `pyotp` 2.10.0 | `D:\democase\ai\.venv`（專題的 Python 虛擬環境） | 官方 PyPI |
| `segno` 1.6.6 | 同上 | 官方 PyPI |
| `cryptography` 50.0.2 | 同上（原本就因 Google 登入裝了，這次在 `requirements.txt` 明寫） | 官方 PyPI |

### 怎麼安裝（新電腦或組員）

```bash
D:/democase/ai/.venv/Scripts/python.exe -m pip install -r requirements.txt
```

### 怎麼移除

```bash
D:/democase/ai/.venv/Scripts/python.exe -m pip uninstall pyotp segno
```

然後刪掉 `requirements.txt` 裡的 `pyotp==2.10.0`、`segno==1.6.6` 兩行（`cryptography` 是 Google 登入也要用的，不要移除）。整個 `.venv` 資料夾刪掉也會一起移除。

### 管理員手機遺失時的緊急重設

在伺服器上（專案資料夾）執行，只有能登入伺服器的人能用：

```bash
D:/democase/ai/.venv/Scripts/flask.exe --app run.py reset-2fa 帳號
```

重設後這個帳號下次登入要重新掃 QR code。指令會寫進操作紀錄。
