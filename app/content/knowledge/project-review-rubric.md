# 專題審查學習目標與評量對照表

資訊軟體開發組與商務網站經營組

依據114 學年度期中審查、1142 學期複評及二次複評結果整理

本文件將各階段審查意見轉換為可觀察、可驗收的學習目標，供專題指導、期中檢核、複評補正及課程成效評量使用。核心原則是先確認問題與需求，再完成系統或商業成果，最後以測試、數據與修正證據完成驗收。

| 資料範圍 | 使用原則 |
| :------- | :------- |
| 期中審查 | 確認題目方向、需求、架構、方法與進度是否合理。 |
| 第一次複評 | 確認核心功能、策略與成果是否形成，並檢查修正品質。 |
| 第二次複評 | 針對殘餘缺失逐項驗收，不以增加內容取代真正改善。 |

## 一三階段學習目標與驗收架構

| 階段 | 核心目的 | 學習目標 | 主要驗收證據 |
| :--- | :------- | :------- | :------- |
| 期中審查 | 確認方向正確 | 能界定真實問題、使用者、需求、範圍及執行方法。 | 需求分析、功能或經營架構、進度表、初步成果。 |
| 第一次複評 | 確認成果形成 | 能完成核心功能或策略，並依資料、操作或測試證明成果。 | 可操作系統、網站數據、企劃書、測試紀錄。 |
| 第二次複評 | 關閉剩餘缺失 | 能逐項回應評審意見，呈現修正前後差異及最終結果。 | 意見對照表、現場展示、最終測試、前後版本。 |

## 二共同課程學習目標

| 代碼 | 能力 | 學習目標 | 達成指標 |
| :--- | :--- | :------- | :------- |
| CLO1 | 問題與需求界定 | 辨識真實問題、目標使用者及專題範圍。 | 問題、使用者與需求之間具有清楚對應。 |
| CLO2 | 專業方案設計 | 運用系統分析或商業分析方法完成專題方案。 | 方法與題目性質相符，且可實際執行。 |
| CLO3 | 成果整合 | 將功能、資料或策略整合為完整成果。 | 各部分具有關聯，不是互不相干的功能或活動。 |
| CLO4 | 驗證與評估 | 利用測試、營運數據或使用者回饋驗證成效。 | 提出可追溯的數據、紀錄或操作結果。 |
| CLO5 | 回饋修正 | 依評審意見完成具體且可證明的改善。 | 每項意見均有修正措施及完成證據。 |
| CLO6 | 表達與協作 | 清楚展示成果、回答問題並說明個人貢獻。 | 全體組員參與，且能回答本人負責內容。 |
